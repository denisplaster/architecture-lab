Starting a React Project

Create a React app with Vite, see what the template gives you, and organize it two ways: for a small project and for a large one. Then choose the plugins and libraries each size needs.

You build
A React + TypeScript app called my-app.
You need
Node.js 20.19 or newer (22 LTS is best), Git, VS Code.

Create the project

Minutes 0–8

Vite is the standard way to start a React app. It gives you a dev server that reloads instantly and a production build.

Terminal
npm create vite@latest my-app -- --template react-ts

It asks three questions:

QuestionAnswerWhy
Ok to proceed?Enternpm downloads Vite's create tool.
Which linter to use?OxlintFast and needs no setup. A large project picks ESLint for its plugins (part 5).
Install with npm and start now?NoWe look inside before it runs.
Terminal
cd my-app
npm install
npm run dev

Open http://localhost:5173 to see the demo page. Press Ctrl+C in the terminal to stop it. Then save a starting point and open the folder in VS Code:

Terminal
git init
git add -A
git commit -m "Create project from Vite template"
code .

Minutes 8–15

Clean up

git rm deletes the files and records it in Git. It is the same command on Windows, macOS and Linux.

Terminal
git rm -r src/assets src/App.css public/icons.svg
Replace filesrc/App.tsx
function App() {
  return (
    <main>
      <h1>My App</h1>
    </main>
  )
}

export default App
Replace filesrc/index.css
:root {
  font-family: system-ui, 'Segoe UI', Roboto, sans-serif;
  line-height: 1.5;
  color-scheme: light dark;
}

body {
  margin: 0;
}

main {
  max-width: 40rem;
  margin: 0 auto;
  padding: 2rem 1rem;
}

Check that it still builds, then commit. The build runs TypeScript, so it catches any import of a file you deleted.

Terminal
npm run build
git add -A
git commit -m "Remove template demo"

Structure for a small project

Minutes 15–25

For one or two developers, a handful of screens and one API. Organize by kind of code: to find a file, ask what kind of thing it is.

  • Imports flow one way: pages use components and hooks, hooks use lib, and everything may use types.
  • Stay flat. Don't nest folders inside these until a folder gets crowded.
  • A component only one page uses can sit next to that page until a second page needs it.

Create it

macOS / Linux
mkdir src/components src/pages src/hooks src/lib src/types
Windows PowerShell
mkdir src/components, src/pages, src/hooks, src/lib, src/types
New filesrc/pages/HomePage.tsx
export function HomePage() {
  return (
    <main>
      <h1>My App</h1>
    </main>
  )
}
Replace filesrc/App.tsx
import { HomePage } from './pages/HomePage'

function App() {
  return <HomePage />
}

export default App

Git doesn't save empty folders. Each folder appears in a commit once it holds a file.

Terminal
npm run build
git add -A
git commit -m "Small project structure"

Structure for a large project

Minutes 25–35

For several developers or teams and many screens. Organize by feature: everything about courses lives in one folder, and folders follow rules about who may import whom.

  • A feature imports from shared/, never from another feature's folders.
  • Code outside a feature imports only its index.ts.
  • shared/ never imports from features/ or app/.
  • A lint rule enforces these, so the structure survives new teammates (part 5).

Each feature has one public file

Examplesrc/features/courses/index.ts
// The only file code outside this feature may import.
export { CoursesPage } from './pages/CoursesPage'
export type { Course } from './types'

The @/ alias

Deep folders lead to imports like ../../../shared/ui/Card. An alias lets you write @/shared/ui/Card from anywhere. Vite 8 can read the alias straight from TypeScript's settings, so you define it once.

Add inside compilerOptionstsconfig.app.json
"paths": {
  "@/*": ["./src/*"]
},
Replace filevite.config.ts
import react from '@vitejs/plugin-react'
import { defineConfig } from 'vite'

// https://vite.dev/config/
export default defineConfig({
  plugins: [react()],
  resolve: {
    // Read the "@/..." alias from tsconfig.app.json
    tsconfigPaths: true,
  },
})

When to switch from small to large

  • More than one team, or more than four or five people, work in the app.
  • A folder such as components/ passes 15 to 20 files.
  • One change touches four or more folders.
  • People keep hitting merge conflicts in the same files.

Until then, stay small. It has fewer folders and fewer rules, so changes are faster.

Plugins and libraries

Minutes 35–45

A plugin changes how a tool works: Vite, the linter, or your editor. A library is code your app imports. Add each one when you have the problem it solves.

Start with these (every project)

TypeScriptCatches mistakes before the browser does.Included

Where Vite plugins go

Every Vite plugin is a function in the plugins list. This is the large project's vite.config.ts with Tailwind added next to React:

Examplevite.config.ts
import tailwindcss from '@tailwindcss/vite'
import react from '@vitejs/plugin-react'
import { defineConfig } from 'vite'

// https://vite.dev/config/
export default defineConfig({
  plugins: [react(), tailwindcss()],
  resolve: {
    // Read the "@/..." alias from tsconfig.app.json
    tsconfigPaths: true,
  },
})

Tailwind also needs @import "tailwindcss"; as the first line of src/index.css.

Exit questions

  1. 1. Two people are building an app with five screens. Which structure do they use, and which two tools from this part do they add first?
  2. 2. Why does other code import CoursesPage from @/features/courses and not from @/features/courses/pages/CoursesPage?
Answers for the teacher

1. The small structure. Good first additions are Prettier and React Router; Vitest is a strong third. The large structure's rules cost time on every change and protect nothing at this size.

2. index.ts is the feature's public API. The feature can then move or rename its internal files without breaking anyone, and a lint rule can block every other way in.
